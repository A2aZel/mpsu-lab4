# Выбор операции переключателями

У CYBERcobra уже есть 16 операций АЛУ. Программа `program_operations.mem`
позволяет выбрать одну из них переключателями, передать два числа и получить
результат. Это отдельная программа для того же процессора. Обычная программа
варианта 12 сохранена: без выбора режима `operations` запускается она.

## Что задают переключатели

В режиме `operations` все 16 переключателей делятся на три поля:

```text
SW15 … SW12 | SW11 … SW6 | SW5 … SW0
 операция  |  число A  |  число B
  4 бита   |  6 бит    |  6 бит
```

Обычно A и B — целые числа от 0 до 63. Для знаковых операций те же шесть
бит означают числа от −32 до 31: `100000` — −32, `111111` — −1.
Знаковыми являются только A у SRA и оба числа у SLTS, LTS, GES.
У остальных операций A и B берутся как числа от 0 до 63.

| SW15…SW12 (HEX) | Операция | Результат |
|---|---|---|
| `0` | ADD | A + B |
| `1` | SUB | A − B |
| `2` | AND | Побитовое И |
| `3` | OR | Побитовое ИЛИ |
| `4` | XOR | Побитовое исключающее ИЛИ |
| `5` | SLL | Сдвиг A влево на B позиций, справа нули |
| `6` | SRL | Сдвиг A вправо на B позиций, слева нули |
| `7` | SRA | Сдвиг знакового A вправо с сохранением знака |
| `8` | SLTS | 1, если знаковое A < B; иначе 0 |
| `9` | SLTU | 1, если беззнаковое A < B; иначе 0 |
| `A` | EQ | 1, если A = B; иначе 0 |
| `B` | NE | 1, если A ≠ B; иначе 0 |
| `C` | LTS | 1, если знаковое A < B; иначе 0 |
| `D` | GES | 1, если знаковое A ≥ B; иначе 0 |
| `E` | LTU | 1, если беззнаковое A < B; иначе 0 |
| `F` | GEU | 1, если беззнаковое A ≥ B; иначе 0 |

В сдвигах учитываются только младшие пять бит B: фактический сдвиг —
`B & 31`, то есть от 0 до 31. Например, B=33 означает сдвиг на 1.
Вычисления дают 32-битный результат; отрицательные результаты записываются
в дополнительном коде. Например, 3−5 даёт `FFFFFFFE` (−2).

SLTS/SLTU записывают результат сравнения непосредственно. LTS/GES/LTU/GEU,
EQ/NE — условия перехода: программа выполняет соответствующий условный
переход и превращает его результат в удобное для наблюдения число 0 или 1.

## Проверить в Vivado на Windows

Ниже предполагается, что новая папка репозитория называется `mpsu-lab4-new`
и находится в `Документы`. Если путь другой, замените его в команде.

1. Откройте Vivado без открытого проекта. В нижней **Tcl Console** выполните:

   ```tcl
   set ::lab4_walkthrough_program_mode operations
   source [file join $env(USERPROFILE) Documents mpsu-lab4-new Lab4_CYBERcobra walkthrough setup_gui.tcl]
   ```

   Скрипт создаст проект, скопирует выбранную программу как `program.mem`
   и настроит тестбенч для проверки операций.

2. Откройте **Sources → Simulation Sources → tb_lab4_demo**. Найдите строку:

   ```systemverilog
   logic [15:0] sw = 16'h03b8;
   ```

   Для примера ADD, A=5, B=3 замените её на:

   ```systemverilog
   logic [15:0] sw = 16'h0143;
   ```

   Здесь `0143` — все 16 переключателей сразу, а не само число A.
   В двоичной записи это `0000 000101 000011`: операция 0, A=5, B=3.
   Исходное `03B8` в этом режиме означает ADD, A=14, B=56, результат 70
   (`00000046`).

3. Нажмите **Ctrl+S → Run Simulation → Run Behavioral Simulation**.
4. В **Tcl Console** выполните:

   ```tcl
   source [file join $env(USERPROFILE) Documents mpsu-lab4-new Lab4_CYBERcobra walkthrough wave_demo.tcl]
   ```

5. Нажмите **Run All → Zoom Fit** и поставьте курсор в конце диаграммы.
   Для `0143` ожидаются `test_pass=1`, `out=00000008`, `pc=00000170`
   и сообщение `DEMO_PASS` в консоли. Тестбенч сам вычисляет ожидаемый результат.
6. Для следующего примера измените только `sw`, сохраните файл и нажмите
   **Relaunch Simulation → Run All**. **Restart** не перекомпилирует правки.

Несколько готовых входов:

| `sw` (HEX) | Что проверяем | `out` (HEX) |
|---|---|---|
| `0143` | 5 + 3 | `00000008` |
| `1143` | 5 − 3 | `00000002` |
| `20C5` | 3 AND 5 | `00000001` |
| `5142` | 5 << 2 | `00000014` |
| `7E02` | −8 >> 2 с сохранением знака | `FFFFFFFE` |
| `A145` | 5 = 5 | `00000001` |
| `CFC1` | Знаковое −1 < 1 | `00000001` |
| `EFC1` | Беззнаковое 63 < 1 | `00000000` |

Вход можно собрать формулой:
`sw = (операция << 12) | ((A & 63) << 6) | (B & 63)`.
Для отрицательного A или B берутся его младшие шесть бит.

## Проверить на плате Nexys A7-100T

Готовая прошивка прежнего варианта 12 не содержит меню операций. Для нового
режима нужно собрать новый `.bit` из проекта, созданного командой выше.

1. Закройте симуляцию и нажмите **Run Synthesis → Run Implementation →
   Generate Bitstream**, дожидаясь окончания каждого этапа.
2. Подключите плату и откройте **Open Hardware Manager → Open Target →
   Auto Connect → Program Device**. Выберите созданный `.bit` и нажмите
   **Program**.
3. Выставьте SW15…SW12, A и B. Например, для 5+3 включены
   **SW8, SW6, SW1, SW0**, остальные выключены: это `0143`.
4. Удерживайте **CPU_RESET**, один раз нажмите и отпустите **BTND**, затем
   отпустите **CPU_RESET**. Сброс синхронный: без импульса BTND он не
   сбрасывает процессор.
5. Нажимайте и отпускайте **BTND**, выполняя программу по одной команде.
   Для ADD достаточно 19 рабочих нажатий после сброса. Для любого выбора
   достаточно 50: лишние нажатия в конце сохраняют результат.

В конце PC равен `00000170`. Индикаторы PC показывают только младшие 8 бит,
поэтому на плате будет **`70`**. Светодиоды показывают младшие 16 бит результата,
а индикаторы `out` — младшие 8 бит. Полные 32 бита видны в симуляции.
Число рабочих нажатий до результата — `19 + 2 × номер_операции`, плюс одно
для истинного условия у операций A…F. Номер операции здесь от 0 до 15.

Менять переключатели следует перед сбросом и запуском. После завершения
программа стоит на `J 0`: изменение SW само по себе не запускает новое
вычисление. Для нового примера повторите сброс с BTND и рабочие нажатия.
Отдельного сигнала готовности или светодиода готовности в этом режиме нет.

Из командной строки Vivado сборка того же режима запускается из
`Lab4_CYBERcobra`:

```text
vivado -mode batch -nojournal -nolog -source build_bitstream.tcl -tclargs operations
```

## Вернуться к варианту 12

В новой Vivado без открытого проекта выполните:

```tcl
set ::lab4_walkthrough_program_mode default
source [file join $env(USERPROFILE) Documents mpsu-lab4-new Lab4_CYBERcobra walkthrough setup_gui.tcl]
```

В этом режиме `03B8` снова означает исходное число варианта 12, из которого
программа собирает биты с чётными номерами: результат `00000014`.
Выбор другой программы требует новой сборки `.bit` для платы. Изменение
операции или чисел переключателями внутри режима `operations` новой сборки
не требует.

## Где находится реализация

- `program_operations.mem` — программа из 93 машинных команд; последняя
  удерживает результат по адресу `170` (HEX).
- `program_operations.txt` — читаемая запись той же программы.
- `alu.sv` — сами арифметические, логические операции, сдвиги и сравнения.
- `CYBERcobra.sv` — выполнение команд, регистры и выбор следующего PC.
- `walkthrough/tb_lab4_demo.sv` — вход `sw` и автоматическая проверка результата.
- `walkthrough/setup_gui.tcl` — выбор программы для проекта Vivado.

## Проверка

В Icarus Verilog 13.0 прошли 432 граничных примера для всех операций и
отдельный полный перебор **65 536** значений SW. Для каждого входа сверены
результат, точное число команд, конечный PC, запрет записи в конечном цикле
и удержание результата на двух дополнительных тактах. Эталон полного прогона
вычислялся независимо в Python. Также проверены изменение только `sw`,
отклонение неправильного результата и продолжение после `$finish`.

В этой программе `r6` не используется: его неопределённое значение на диаграмме
не является ошибкой. Для выбранной операции смотрите `selected_op`,
`input_a`, `input_b`, `expected_result`, `out` и `test_pass`.

Здесь используются все имеющиеся операции АЛУ; умножение, деление и память
данных не добавлялись. Проверка на физической плате и запуск новой версии
в Vivado/XSim ещё не проводились.
